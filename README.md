CampusConnect is a four-step registration form (Identity, Security, Profile, Review) built with plain HTML, CSS and JavaScript. Nothing is sent or saved anywhere. HTML constraint attributes (required, pattern, type="email", minlength, maxlength) are the first layer of validation, from Module 5. A rule-driven JavaScript engine adapted from Module 8 adds the rules HTML can't express, like the exact student.gsu.edu domain, the password strength rules, the password confirmation match and the 1–3 interests limit. Validation timing follows Module 6: a field is checked on blur, rechecked on input once it is invalid so errors clear as soon as they're fixed, and every field is checked again on final submit. From Module 9, a failed Next or Submit shows an error summary at the top with links that open the right step and focus the field, and each field is connected to its error message with aria-invalid and aria-describedby. The password checklist shows "✓ Met" or "✗ Needed" as text, so it doesn't depend on color. The steps are shown and hidden instead of rebuilt, so Back never loses data. The Review step is rebuilt each time it opens and never shows the password. One trade-off I chose: pressing Enter on steps 1–3 acts like Next and only checks the current step. A full check there would flag empty fields on steps the user hasn't seen yet, which is confusing. The full check still runs on the final submit.
